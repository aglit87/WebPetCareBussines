## Context

Мотивация — в proposal.md (Why). Ключевые факты текущего состояния, влияющие на подход:

- `shared/api/baseQueryWithReauth.ts` импортирует `entities/auth/model/slice` (runtime) и `app/store` (типы) — единственная runtime-инверсия в дереве.
- Мок-бэкенд (`shared/api/mock/`) типизируется DTO из `entities/*` (type-only) и запускается безусловно в `main.tsx`.
- В 10 из 10 data-виджетов продублированы экраны ошибки/скелетона с идентичной разметкой.
- Один источник слотов расписания отсутствует: `db.ts` (TIME_SLOTS) и `ScheduleWidget` (HOURS) держат копии.
- Кэш RTK Query при смене пользователя не сбрасывается.
- Персист в localStorage выполняется внутри редукторов auth/business слайсов.
- Тестов, линта и CI нет; чистая логика (reauth, автомат auth, date-утилиты, zod-схемы) от них выигрывает больше всего.

## Goals / Non-Goals

**Goals:**
- Восстановить направление зависимостей FSD: `shared` не должен знать о `entities`/`app`.
- Получить переключаемый seam моков (разработка с моками, прод без них) без изменения контракта `/api/*`.
- Одним источником правды на контракты (zod) и на константы (слоты, OtpPurpose).
- Убрать дублирование UI-состояний виджетов, сброс кэша при потере авторизации.
- Инфраструктура качества: Vitest, ESLint, CI — с тестами на самую рискованную чистую логику.

**Non-Goals:**
- Не меняем контракты API `/api/*` — ни для клиента, ни для будущего бэкенда.
- НЕ вводим универсальный контекст тенанта вместо query-параметра `?type=` (отдельная тема).
- НЕ добавляем форму-библиотеку и не рефакторим модалки (key-remount оставляем).
- НЕ вводим redux-persist и сторонние state-библиотеки.
- НЕ создаём capability-спеки: поведение не меняется (`skip_specs: true`).

## Decisions

### D1. Реал-логика — фабрика с инъекцией вместо импортов

Из `shared` убираем все импорты домена/приложения. Вместо модульной константы делаем фабрику:

```ts
// shared/api/createBaseQueryWithReauth.ts (generic RTK-only)
export interface ReauthDeps {
  refreshUrl: string;
  getRefreshToken: (state: unknown) => string | null;
  onTokensRefreshed: (tokens) => void;      // dispatch tokensRefreshed
  onAuthFailed: () => void;                 // dispatch loggedOut + reset cache
}
export const createBaseQueryWithReauth = (deps: ReauthDeps): BaseQueryFn => { ... };
```

Фабрика ничего не знает про `entities`/`app` — только про RTK Query. Сборка проводов (селекторы токенов, действия слайса, `api.util.resetApiState`) происходит в `app/store` — единственная точка, которая и так знает всю систему. Логика общей гонки refresh (`refreshPromise`) сохраняется как есть.

Альтернативы: (а) оставить как есть — инверсия остаётся; (б) перенести реал в `entities/auth` и переиспользовать оттуда — тогда остальные entity API начинают зависеть от auth-домена (соседний слой, но связность выше). Выбрана фабрика: shared не зависит ни от чего, конфигурация собирается там, где это уместно.

### D2. Мок-бэкенд переезжает в peer-слой `src/mocks/`

`src/shared/api/mock/*` → `src/mocks/` (рядом с `app/`, не внутри shared). Этот слой вправе импортировать entities (типы DTO) и shared (хелперы). Хэндлеры начинают валидировать тела запросов теми же zod-схемами, что и клиент: `parse` → при ошибке `400`. Это превращает MSW в честный экземпляр контракта, а не второй источник правды.

Альтернатива: оставить в shared с локальным дублированием типов — дубль контрактов хуже. `src/mocks/` не расширяет стэк FSD, а выступает адаптером между слоями.

### D3. Включение моков — по флагу, не безусловно

`enableMocking()` вызывается в `main.tsx` только когда `import.meta.env.VITE_USE_MOCKS === '1'` (dev-по умолчанию) или присутствует `?mock=1` в URL (перезапись для локальных проверок). Сборки без флага не стартуют MSW и ходят в `fetchBaseQuery` на `/api` как есть.

### D4. Общие состояния виджетов в `shared/ui`

Два новых компонента (это app-слойные композиты, их место в репо, а не в `petcare-storybook-ui`):
- `WidgetError({ onRetry })` — единый экран «Нет соединения с сервером».
- `WidgetSkeleton({ children })` — фрейм-контейнер скелетонов.

Пустые состояния остаются уникальными у каждого виджета. 10 дублей `XxxError`/`XxxSkeleton` удаляются.

### D5. Сброс кэша при потере авторизации

`onAuthFailed` (D1) вызывает `api.util.resetApiState()` (все reducerPath'и из `app/store`). Сброс — только при потере сессии (logout/истёкший refresh), не при обновлении токенов, чтобы не устраивать «шторм» перезапросов на каждом refresh. Утечка данных между пользователями исключается.

### D6. Персист — наружу из редукторов

Запись в localStorage уезжает из `auth`/`business` слайсов в app-слой: подписка `store.subscribe` с фильтром по слайсу и небольшой типизированный хелпер `shared/lib/storage.ts` с версионированным префиксом (`petcare.v1.*`) и проверкой версии при загрузке (несовпадение → очистка или миграция). Редукторы становятся чистыми.

Альтернатива: redux-persist — новая зависимость ради двух слайсов, отклонено.

### D7. Единый источник констант и типов

- `SCHEDULE_HOURS` — в `entities/schedule/model/config.ts`; `db.ts` (после переезда в `src/mocks/`) и `ScheduleWidget` импортируют его.
- `OtpPurpose` — единый экспорт из `entities/auth/model/types`, mock импортирует его (сейчас дубль в `mock/authDb.ts`).
- Subtitle кабинета берётся из `dashboard.subtitle`; до получения данных — fallback на `config.label`, хардкод «вторник, 24 июня» удаляется.

### D8. Качество: Vitest, ESLint, CI

- Vitest (нативно для Vite): `vitest.config.ts` как отдельный конфиг или поле `test` в vite; скрипты `test`, `test:watch`. Unit-тесты без браузера.
- ESLint + typescript-eslint (flat config) + плагин react hooks; скрипт `lint`.
- GitHub Actions `.github/workflows/ci.yml`: install → lint → `tsc -b` (build) → vitest run.
- Первый контур тестов — чистая логика: гонка 401/refresh, автомат auth-слайса, `entities/schedule/model/date.ts`, zod-схемы request/response, `getErrorMessage`, пара мок-хэндлеров.

Порядок внедрения — фазами (см. Migration Plan), каждая фаза оставляет приложение рабочим. CLAUDE.md обновляется по ходу (раздел API-конвенции и MSW).

## Risks / Trade-offs

- [Рефакторинг реала ломает 401-гонку под нагрузкой] → Сначала пишем unit-тест на существующее поведение (до миграции), затем переписываем фабрику — тест остаётся зелёным. В моках access-токен живёт 5 минут, что позволяет вручную проверять refresh.
- [Переезд `shared/api/mock` ломает Storybook] → `.storybook/preview.tsx` импортирует `enableMocking`/`browser`; пути меняются в той же фаче, что и переезд, worker стартует в stories как раньше.
- [`resetApiState` на любом refresh вызовет перезапросы] → Сброс только по `onAuthFailed`, отдельный кейс покрывается тестом.
- [skip_specs: true не пройдёт validate] → Опция официальная: validate допускает ноль дельт при `skip_specs: true`; проверяем `openspec validate` перед завершением планирования.
- [ESLint/CI как новая обязанность может отвлекать] → Конфиг минимальный (ошибки уровня severity, без мелочевки); CI запускается только на push/PR.

## Migration Plan

1. **Фаза 0 — красная зона**: добавить Vitest + тесты на существующую чистую логику (до правок) — зелёная сетка как предохранитель.
2. **Фаза 1 — реал по-новому**: D1 фабрика + проводка в `app/store`; D5 сброс кэша; тесты на гонку остаются зелёными.
3. **Фаза 2 — моки**: D2 переезд в `src/mocks/`, zod-валидация в хэндлерах; D3 флаг включения; D7 константы/типы.
4. **Фаза 3 — UI-долг**: D4 общие виджеты-состояния; D6 персист-помощник.
5. **Фаза 4 — каркас качества**: D8 ESLint + CI; обновление CLAUDE.md.

Откат: каждая фаза — отдельный коммит; при регрессе откатываются только соответствующие коммиты, остальные не затронуты.
